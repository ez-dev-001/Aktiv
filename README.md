# ЮК «АКТИВ» — новый сайт

Next.js 16 (App Router) + TypeScript + Tailwind 4 + Sanity. Замена WordPress-сайту
[aktiv-alb.com](https://aktiv-alb.com). Контент со старого сайта не переносится.
Со старого сайта сохранён логотипный красный `#FA2163`; остальная палитра
настроена вокруг него заново — см. «Решения, которые стоит знать до правок».

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev             # http://localhost:3000
```

Сайт запускается без единой переменной окружения: контент пока статический,
из `lib/content.ts`. Sanity и Firebase подключаются позже и ничего не ломают,
пока переменные пустые.

```bash
npm run build         # продакшен-сборка
npm run typecheck     # tsc --noEmit, strict
npm run check:schema  # сторож схем Sanity, см. ниже
```

## Как проверить Sanity

В проекте есть страница диагностики: **<http://localhost:3000/sanity-check>**.
Она дёргает API прямо сейчас и показывает, что именно не так. Смысл в том,
чтобы отличать причины друг от друга — «не работает» бывает пяти разных видов,
и лечатся они по-разному.

### Порядок

1. Открыть `/sanity-check` **до** всякой настройки. Должно быть: projectId
   не задан, запрос пропущен, источник контента — статика. Это нормальный
   рабочий стан: сайт живёт и без Sanity.
2. Завести бесплатный проект на [sanity.io/manage](https://www.sanity.io/manage),
   скопировать **Project ID**.
3. Дописать в `.env.local`. Один и тот же id **дважды**: `NEXT_PUBLIC_*` читает
   сайт, `SANITY_STUDIO_*` — студия. Это разные бандлы, префиксы не
   взаимозаменяемы, и спотыкаются об это чаще всего.

   ```ini
   NEXT_PUBLIC_SANITY_PROJECT_ID=ваш_id
   NEXT_PUBLIC_SANITY_DATASET=production
   SANITY_STUDIO_PROJECT_ID=ваш_id
   SANITY_STUDIO_DATASET=production
   ```

4. **Перезапустить `npm run dev`** — Next читает `.env.local` один раз при старте.
5. Обновить `/sanity-check`. Теперь запрос уходит по-настоящему. Ожидаемо:
   API отвечает, датасет пустой, источник всё ещё статика.
6. Наполнить демо-контентом. Нужен токен с правом записи:
   sanity.io/manage → API → Tokens → Add token → **Editor**, в `.env.local`
   как `SANITY_API_WRITE_TOKEN`. Затем:

   ```bash
   npm run seed
   ```

   Скрипт создаст 6 специалистов, 4 категории и 5 практик — по одной на каждый тип цены,
   чтобы было видно, что `priceSpec` работает во всех трёх режимах.
   Идемпотентно: у документов детерминированные `_id`, повторный запуск
   обновляет, а не плодит дубли.
7. Обновить `/sanity-check` ещё раз. Должно стать: **источник контента — Sanity**.
   Открыть главную — блок практик теперь читается из Sanity.
8. `npm run studio` → <http://localhost:3333>, поправить название категории,
   обновить главную. Изменение приедет (ревалидация 300 с, либо перезапуск dev).

### Что означает каждое состояние

| Что видно | Что это значит |
|---|---|
| projectId не задан | Не дошли до шага 3, либо не перезапустили сервер |
| «не схоже на id» | Скопировали название проекта вместо id. Sanity выдаёт 8+ строчных букв и цифр |
| Запрос упал, 401/403 | Sanity не различает «проекта нет» и «датасет приватный». Сначала звери́те id и имя датасета — это частіша причина |
| Датасет пустой | Не запускали `npm run seed`, либо у токена нет прав Editor |
| Источник — статика | Нормально, пока в датасете нет ни одной категории. Переключится само |
| Практики без категории | Такая практика не попадёт ни в меню, ни на главную — ровно то, что случилось с 17 страницами старого сайта |

Страница закрыта от индексации и не залинкована с сайта. Перед сдачей её можно
удалить — файл `app/sanity-check/page.tsx`.

### Сторож схем

`npm run check:schema` ловит одну ошибку, но самую тихую: поле ссылается
на тип, который забыли зарегистрировать в `schemas/index.ts`. TypeScript её
не видит — для него `to: [{ type: 'teamMember' }]` просто строка. Падает
только студия, при запуске, сообщением «Unknown type: teamMember».

Скрипт висит на `prestudio`, то есть `npm run studio` сам его прогонит
перед запуском. Ловит два случая: тип не объявлен нигде и тип объявлен,
но не попал в массив `schemaTypes`.

Именно на этом споткнулись в первый раз: `practice.lawyers` ссылался на
`teamMember`, а самой схемы не было — она значилась в планах этапа 6.

### Локализованные поля внутри объектов

Грабли, на которые легко наступить повторно. Внутри `priceSpec` поля `note`
и `percentBase` — это `localeString`, то есть объекты `{ _type, ua, en, ru }`.
Проецировать в GROQ `price` целиком **нельзя**: наружу уедет объект там, где
компонент ждёт строку, и React уронит всю страницу с «Objects are not valid
as a React child». Поэтому `price` в `queries.ts` разбирается по полям,
а локализованные идут через `coalesce`.

Страховка на этот случай стоит в `lib/sanity/content.ts`: `flattenLocale`
схлопывает любой объект с ключом `ua` в строку. Правильное место для
локализации — GROQ, но один забытый `coalesce` не должен стоить страницы.
Причина, по которой страховка нужна: типы TypeScript описывают то, что мы
**ожидаем** получить, ответ GROQ приходит как `any`, и расхождение между
ними компилятор не видит.

### Как устроено подключение

`lib/sanity/client.ts` возвращает `null`, пока `projectId` не задан. Поэтому
`lib/sanity/content.ts` пробует Sanity и молча откатывается на `lib/content.ts`,
если Sanity не настроен, упал или вернул пусто. Компонентам всё равно, откуда
пришли данные: форма объектов одна. Это значит, что подключение Sanity —
дописать четыре строки в `.env.local`, а не рефакторинг, и что падение Sanity
в проде не роняет сайт.

## Решения, которые стоит знать до правок

**Палитра настроена вокруг логотипа, а не скопирована со старого сайта.**
Первый этап требовал перенести её один в один, но при сборке стало видно, почему
на старом сайте цвет ощущался дешёвым, и палитру перенастроили. Что изменилось
и зачем — в комментарии над `@theme` в `app/globals.css`, там же единственное
место, где цвета вообще существуют. Коротко:

- `--color-accent: #fa2163` не тронут — это пиксели логотипа, идентичность;
- чернила ушли из чисто-синего `#070143` в сливовый `#140b33`: с малиновым
  синий читается как вторая, чужая система;
- бумага и нейтрали потеплели — холодный `#fafbfe` под малиновым отдавал в синеву;
- акцент разведён по ролям. `--color-accent` только для графики (линия, точки,
  иконки, заливки кнопок), `--color-accent-ink` для текста на светлом,
  `--color-accent-soft` для текста на тёмном. Причина не эстетическая:
  `#fa2163` на белом даёт 3.8:1, и мелкий текст им набирать нельзя;
- `h1` набирается весом 400, а не 600: серифный дисплей в 68 px при 600 забивает
  полосу набора.

Вернуть исходную палитру = откатить блок `@theme` и правило `h1`.

**Линия дела — единственный сквозной приём.** `components/site/CaseLine.tsx`
собирает путь из реальных `offsetTop` секций, перечисленных в `STATIONS`
в `app/[lang]/page.tsx`. Чтобы добавить станцию: добавить секцию с `id`
и строку в `STATIONS`. Ничего больше. Пересчёт на resize, ResizeObserver
и после `document.fonts.ready`.

Живой её делают четыре вещи, все в том же файле:

1. **Демпфирование** — голова догоняет цель с коэффициентом `EASE = 0.12`
   за кадр, а не привязана к скроллу один в один. Это главное отличие
   дорогой анимации от дешёвой и стоит четырёх строк.
2. **Градиент** — стопы `#caselineGrad` двигаются вместе с головой:
   у неё полная насыщенность, дальше назад приглушённо. Линия читается
   как след, а не как заливка.
3. **Комета** — окно `COMET = 110 px` пути, вырезанное шаблоном
   `dasharray: 0, зазор, штрих, остаток`. Единственный способ показать
   произвольный отрезок пути без второго `<path>` с обрезкой.
4. **Прибытие** — кольцо на станции, чистый CSS: селектор
   `.caseline-station[data-on="true"] .caseline-dot::after` начинает
   совпадать в момент смены атрибута, и анимация проигрывается один раз.

Цикл `rAF` сам останавливается, когда догнал цель, — в покое кадры не жжёт.

**Логотип векторный.** `components/site/Logo.tsx` — знак снят с растра клиента
(`logotip_3.png`, 1051×391) замером по пикселям, а не на глаз: внешний Ø кольца 167,
штрих 23, у хвоста стрелки вырез. Кольцо **разомкнуто справа** — стрелка проходит
сквозь него с зазором, и именно это делает знак знаком. Нужен в четырёх местах:
шапка, футер, кнопка «наверх» (повёрнут стрелкой вверх) и favicon, — растр туда
не тянется. `currentColor`, поэтому работает малиновым на бумаге и белым на тёмном.

**Плавающий блок связи.** `FloatingActions.tsx`. На старом сайте здесь висел
красный кружок с телефоном, перекрывавший контент. Здесь то же место, но блок
прячется, когда форма заявки в кадре (незачем дублировать CTA перед глазами),
«наверх» появляется только после полутора экранов, отступы считаются от
`env(safe-area-inset-bottom)` — иначе на айфонах с жестовой панелью кнопка
уезжает под неё, — и цель нажатия у каждого элемента 48 px.

**«Нам довіряють» по умолчанию без логотипов — и это решение, а не заглушка.**
У «Армады», с которой брали референс, тут стена из 24 логотипов корпоративных
клиентов. Копировать механику вслепую нельзя по двум причинам. Юридическая:
чужая торговая марка без письменного согласия владельца — это претензия,
а не социальное доказательство, тем более для юрфирмы. Содержательная:
половина клиентов «Актив» — физлица в делах о ликвидации, ВЛК и семейных
спорах; у них нет логотипов, а анонимность в этих практиках часть услуги.

Поэтому блок стоит на проверяемых фактах самой фирмы: год основания,
300 ликвидаций, 400 процессов, 150 млн ₴, состав команды. Каждый сверяется
с реестрами — это сильнее чужого логотипа. Логотипы включаются, когда
разрешения появятся: `siteSettings.clients`, у каждого логотипа галочка
подтверждения, без неё он на сайт не попадает.

**Ценности на /about и кредо на главной — не дубль.** Текст клиента почти
дословно совпадает с пятью правилами кредо. Если оставить два независимых
списка, посетитель прочитает одно и то же дважды и решит, что это вода.
Поэтому /about объясняет ПОЧЕМУ, главная даёт короткие проверяемые обещания,
и в конце «Принципів роботи» стоит явный мостик (`TrustBridge`).

**GSAP не используется.** Бриф предполагал GSAP + ScrollTrigger, но на два
эффекта (маска заголовков и счётчик) он не отрабатывает свои 70 КБ:
IntersectionObserver плюс один rAF-цикл дают то же самое при нулевом весе.
Если появится третий приём с реальным таймлайном — вернуть, грузя динамически.

**Счётчики.** На старом сайте odometer показывал `89+` и `81,808080` вместо
`400` и `150`: тема грузила `odometer-theme-default.css`, а класс на элементах
был `odometer-auto-theme`, поэтому служебный `<span class="odometer-digit-spacer">8</span>`
оставался видимым. В `Counter.tsx` в DOM пишется одно число, а не столбик разрядов —
тот баг невоспроизводим. SSR сразу отдаёт финальное значение, поэтому без JS цифра на месте.

**Расчёт вилки нельзя доверять клиенту.** `computeQuote` из `lib/quote.ts`
используется и в квизе, и (на этапе 4) в server action. Сумму, пришедшую из браузера,
сервер принимать не должен — только пересчитывать из ответов. Иначе ожидаемая сумма
сделки в CRM и `value` в Meta CAPI правятся из девтулзов.

**Цена — три типа, а не `priceFrom: number`.** Из девяти позиций прайса две не числовые:
«15 % від суми боргу» и «договірна». Отсюда `priceSpec.mode` = `fixed | percent | onRequest`
и поле `unit` для абонентского, которое стоит за месяц.

**Три поломки адаптивности, найденные прогоном по 13 ширинам** — их стоит знать,
потому что все три легко вернуть неаккуратной правкой:

1. **Кредо ломалось на всех мобильных ширинах.** Сетка `grid-cols-[52px_1fr]`
   с тремя детьми: номер, заголовок, абзац. Третий ребёнок уезжал во вторую
   строку ПЕРВОЙ колонки и вёрстся шириной 52 px. Лечится явным `col-start-2`
   у абзаца. На 320 px это давало +1 600 px высоты документа.
2. **Шапка не влезала на 1024 px** — оверфлоу 49 px. Логотип, меню, языки,
   телефон и кнопка разом требуют ~940 px при доступных 944. Теперь элементы
   раскрываются постепенно: языки от 1100 px, телефон от 1240 px.
3. **Прайс-таблица вылезала на 320 px.** Цена стоит `whitespace-nowrap`
   в колонке `auto`, и «від 2 500 ₴ / інстанція» шириной 187 px не помещалась
   рядом с названием. Ниже 420 px цена переносится под услугу.

**Мега-меню снято с раскладки ниже 980px через `display:none`.** `visibility:hidden`
не убирает элемент из `scrollWidth` и давал 188 px горизонтального оверфлоу на телефоне.

**`proxy.ts`, не `middleware.ts`.** В Next 16 соглашение переименовано, старое
печатает deprecation на каждой сборке. `runtime: 'experimental-edge'` тоже убран —
адаптер Netlify разворачивает proxy в edge-функцию сам.

**Пакетный менеджер — npm, не pnpm.** Бриф предполагал pnpm с `shamefully-hoist`
в `.npmrc`, но corepack на Windows не смог поставить шимы в `C:\Program Files\nodejs`
без прав администратора. На npm проект собирается тем же деревом, а hoisting-флаги
не нужны: npm и так раскладывает зависимости плоско. `.npmrc` в проекте нет —
он больше ни для чего не служил. Лок-файл один: `package-lock.json`.

Если позже захочется вернуться на pnpm: поставить его standalone-скриптом
(`iwr https://get.pnpm.io/install.ps1 -useb | iex`, без админа), удалить
`package-lock.json`, вернуть `.npmrc` с `shamefully-hoist=true` и поправить
команду сборки в `netlify.toml`.

## Если Sanity «не подтягивается» — начните отсюда

```
npm run sanity:doctor
```

Скрипт ходит в API напрямую: без CDN, без кеша Next, без SSG и без
фолбэков. Печатает доступ к датасету, число опубликованных документов
по каждому типу отдельно, время последней правки — и главное, **откуда
возьмёт данные каждый блок сайта**.

Последнее и есть самая частая путаница. Сайт переключается на Sanity
не целиком, а по блокам, и каждый блок держится за свой тип документов:

| Блок | Тип | Если пусто |
|---|---|---|
| практики, мега-меню, карточки | `practiceCategory` | статика |
| таблица цен | `practice` с `price` | статика |
| команда | `teamMember` | статика |
| цифры-счётчики | `siteSettings.figures` | статика |
| блог | `post` | статика |
| «Нам довіряють» | `siteSettings.clients` | факты фирмы |

Из Sanity **не** читаются вовсе — это код, и правятся они только там:
кредо (`lib/content.ts → credo`), «шлях справи» (`casePath`),
миссия/визия/ценности, контакты (`contacts`) и калькуляторы
(`lib/quizzes.ts`). `npm run sanity:doctor` печатает этот список
отдельной секцией, чтобы не гадать.

Отсюда следствие, которое ловит почти всех: **можно править практики
сколько угодно, но пока нет ни одного `practiceCategory`, главная
останется статикой.** Запрос категорий вернёт пустой массив, а пустой
ответ — это «нет данных», и `getCategories` отдаст `lib/content.ts`.
Лечится `npm run seed`.

Вторая по частоте — документ создан, но не опубликован. Сайт ходит
с `perspective: 'published'` и черновиков не видит вообще; скрипт
считает их отдельной колонкой.

Запросы скрипт берёт из `lib/sanity/queries.ts`, а не дублирует
у себя — иначе диагностика однажды начнёт проверять не то, что
выполняет сайт.

## Почему правка в Sanity не видна на сайте

Если связь есть (`/sanity-check` зелёный), а изменения не доезжают —
дело в кешировании. Слоёв три, и ведут они себя по-разному.

| Слой | Где | Держит |
|---|---|---|
| CDN Sanity (`useCdn`) | между студией и сервером | ~60 с |
| Кеш `fetch` у Next (`revalidate`) | внутри сервера | 300 с |
| Пререндер страницы (SSG) | продакшен-сборка | до пересборки |

**В dev всё это выключено.** Раньше не было: CDN и `revalidate: 300`
стояли всегда, и правка в студии доезжала до `localhost` до шести минут.
Это и выглядело как «Sanity не подтягивается». Теперь `npm run dev`
ходит мимо CDN и без кеша — правка видна на F5.

**В проде кеш нужен**, поэтому там его гасит вебхук в момент публикации:

1. В `.env.local` задать `SANITY_REVALIDATE_SECRET` — любая длинная строка.
2. `sanity.io/manage` → проект → **API → Webhooks → Create webhook**:

   ```
   URL          https://ВАШ-ДОМЕН/api/revalidate
   Dataset      production
   Trigger on   Create, Update, Delete
   Filter       _type in ["practice","practiceCategory","post","teamMember","siteSettings","quiz"]
   HTTP method  POST
   HTTP Headers x-revalidate-secret: <тот же секрет>
   ```

3. Проверить: открыть `https://ВАШ-ДОМЕН/api/revalidate` в браузере.
   На GET маршрут отвечает короткой справкой о своём состоянии — без
   секрета, без данных и ничего не сбрасывая.

Тег совпадает с `_type` документа, поэтому правка одной статьи гасит
кеш блога и не трогает практики. Пустое или незнакомое тело — гасятся
все теги: перестраховка дешевле застрявшей страницы. Без секрета
маршрут отвечает 501 и не делает ничего.

Защита — общий секрет, без подписи и без лишней зависимости. Этого
достаточно: худшее, что даёт угаданный секрет, — заставить сайт
перечитать собственный контент. Записи в маршруте нет.

`/sanity-check` теперь показывает отставание числом: один и тот же
запрос идёт через CDN и в обход, разница во времени и есть лаг.

## «Нам довіряють» — бегущая лента, редактируется в Sanity

Sanity → **Налаштування сайту** → вкладка **Нам довіряють** → массив
**«Клієнти в стрічці»**. Порядок записей там = порядок в ленте.

У каждой записи четыре поля:

| Поле | Обязательно | Что делает |
|---|---|---|
| Назва компанії | да | То, что видно в ленте, если нет логотипа |
| Логотип | **нет** | SVG/PNG на прозрачном, высотой от 80 px. Показывается ч/б, в цвет — на наведении |
| Сайт клієнта | нет | Запись становится ссылкой |
| Дозвіл | **да** | Без галочки запись не попадает на сайт вообще |

Логотип необязателен намеренно: блок можно заполнить в день сдачи —
одними названиями, набранными шрифтом сайта, — не дожидаясь, пока
клиенты пришлют файлы.

Галочка разрешения обязательна и для логотипа, и для одного названия.
Фильтр стоит в самом GROQ (`clients[permission == true]`), то есть запись
без галочки не доезжает даже до компонента. Причина не формальная: чужая
торговая марка без письменного согласия владельца — это претензия, а не
социальное доказательство, а половина дел фирмы — ликвидация, ВЛК и
семейные споры, где анонимность клиента входит в услугу.

Пустой массив — нормальное состояние: блок показывает проверяемые по
реестрам факты фирмы. Они остаются на месте и когда лента заполнена:
дата основания и 150 млн ₴ доведённых до исполнения — более твёрдый
довод, чем чужой логотип.

**Как устроено движение** (`components/home/ClientTicker.tsx`): дорожка
содержит список чётное число раз, сдвиг идёт на −50 %, поэтому момент
возврата попадает на точно такую же группу и шва не видно при любом
числе записей. Скорость постоянная — 58 px/с, длительность считается из
длины списка, иначе четыре компании проносились бы, а двадцать ползли.
Короткий список повторяется, пока половина дорожки не перекроет широкий
монитор. Наведение и заход клавиатурой ленту останавливают.
При `prefers-reduced-motion` остаётся одна группа без повторов,
перенесённая по строкам. JS ноль: компонент серверный.

## Фотографии — заглушки, их нужно заменить

Все снимки на сайте временные: они подтянуты с Unsplash и стоят
исключительно чтобы увидеть вёрстку с настоящими фотографиями —
пропорции, тон, поведение кадра на телефоне. **Ни один из них не
показывает «АКТИВ», и в продакшен они уйти не могут.**

Замена делается в одном файле — `lib/photos.ts`. Там карта из 13 кадров,
каждый со своим ключом (`hero`, `boardroom`, `documents`, `corridor`…).
Больше нигде в проекте адресов картинок нет.

Когда фотосессия будет:

1. Загрузить снимки в Sanity (или положить в `public/photos/`).
2. В `lib/photos.ts` заменить `id` на путь к своему файлу и переписать `alt` —
   он описывает, что на кадре, и его читают вслух скринридеры.
3. `ratio` — родные пропорции снимка. Нужны, чтобы место под кадр
   резервировалось до загрузки и страница не дёргалась.

Оптимизацию делает CDN (`auto=format` отдаёт AVIF/WebP), а не `next/image`:
компонент `components/site/Photo.tsx` собирает `srcset` сам. Для Sanity
приём ровно тот же — меняется только база адреса.

Карточки команды фотографий **не** получили намеренно: ставить стоковых
людей вместо реальных адвокатов нельзя даже как заглушку. Там монограммы,
и они останутся до настоящих портретов.
