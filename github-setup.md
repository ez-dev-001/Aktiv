# Як закомітити проєкт без командного рядка

Git на комп'ютері зараз не встановлений. Це не проблема: є спосіб, де
командний рядок не потрібен взагалі, а git ставиться сам разом із
програмою.

**GitHub Desktop** — офіційна програма GitHub з інтерфейсом. Вона
приносить із собою власний git, сама авторизується під вашим акаунтом
і робить коміт у два кліки. Це швидше, ніж перетягувати файли в
браузері, і головне — повторні правки теж займають два кліки, а не
нове завантаження всієї папки.

Приблизно **10 хвилин** на все.

---

## Чому саме так, а не перетягуванням у браузер

Перетягнути файли на github.com можна, і git для цього не потрібен. Але:

- у папці проєкту **55 566 файлів** у `node_modules` і ще 2103 у
  `.next`. Їх завантажувати не можна й не треба, і відсіювати їх
  довелося б руками, щоразу;
- поруч лежить `.env.local` з токеном **на запис** до Sanity.
  Завантажити його випадково — означає віддати чужим доступ до всього
  контенту;
- кожна наступна правка — знову ручне завантаження.

З GitHub Desktop усе це вирішує файл `.gitignore`, який у проєкті вже
налаштований: важке й секретне не потрапляє в коміт **автоматично**.
Я щойно дописав у нього `.sanity/` — робочі файли студії, які
пересобираються самі й у репозиторії тільки заважають.

---

## Крок 1. Встановити GitHub Desktop

`desktop.github.com` → **Download for Windows** → запустити інсталятор.

Програма встановиться й одразу запропонує увійти. **Sign in to
GitHub.com** → відкриється браузер → увійдіть під своїм акаунтом (або
створіть, якщо його ще немає) → поверніться в програму.

Далі вона попросить ім'я й пошту для підпису комітів — це просто
підпис автора змін, ставте свої.

---

## Крок 2. Додати папку проєкту

**File → Add local repository** → **Choose…** →

```
C:\Users\Vlada Hnatok\Desktop\Шайко - сайт
```

Програма скаже, що це не репозиторій, і запропонує посилання
**«create a repository»** — натисніть його.

У вікні, що відкриється:

| Поле | Що ставити |
|---|---|
| Name | `aktiv-site` |
| Description | `Сайт ЮК «АКТИВ»` |
| Git ignore | **None** — у проєкті вже є свій `.gitignore`, і він правильний |
| License | None |

**Create repository.**

---

## Крок 3. Перевірити, що не поїде зайве

Це єдиний крок, який варто зробити уважно.

Зліва у вкладці **Changes** буде список файлів. Має бути близько
**70 файлів**. Прогорніть його й переконайтесь, що там **немає**:

- `node_modules/` — жодного файлу звідти
- `.next/`
- `.env.local`
- `.sanity/`

Якщо бачите тисячі файлів — значить `.gitignore` не підхопився.
Не комітьте: скажіть мені, розберемось.

Якщо у списку близько сімдесяти файлів і серед них `app`,
`components`, `lib`, `sanity`, `scripts`, `package.json`,
`netlify.toml` — усе правильно.

---

## Крок 4. Коміт

Унизу зліва два поля. У верхнє (**Summary**) напишіть:

```
Сайт ЮК «АКТИВ»: перша версія
```

Натисніть **Commit to main**.

---

## Крок 5. Опублікувати на GitHub

Угорі з'явиться кнопка **Publish repository**. Натисніть її.

У вікні:

- Name: `aktiv-site`
- **✅ Keep this code private** — галочку **залишити**. Публічність
  нічого не дає, а в коді структура контенту клієнта.

**Publish repository.** Через кілька секунд репозиторій буде на
`github.com/ВАШ-АКАУНТ/aktiv-site`.

Далі — `netlify-test-deploy.md`, крок 3: Netlify побачить цей
репозиторій у списку.

---

## Як робити правки далі

Коли я віддам вам нові файли або ви щось зміните самі:

1. Відкрити GitHub Desktop — зміни з'являться у **Changes** самі
2. Написати коротко, що змінилось, у полі **Summary**
3. **Commit to main**
4. **Push origin** угорі

Netlify побачить пуш і перезбере сайт сам — нічого більше робити не
треба.

## Якщо все ж хочеться командного рядка

Git окремо ставиться однією командою в PowerShell:

```powershell
winget install --id Git.Git -e
```

Після встановлення **закрийте й відкрийте PowerShell заново** —
інакше він не побачить нову команду. Далі працюють команди з
`netlify-test-deploy.md`, крок 2.

Обидва шляхи рівноцінні, GitHub Desktop просто менше про що думати.
