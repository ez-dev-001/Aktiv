# Тестовий деплой на Netlify через GitHub

Мета — побачити сайт на справжньому хостингу, нічого не ламаючи:
домен `aktiv-alb.com` не торкаємось, старий сайт продовжує працювати,
вебхук не налаштовуємо. Адреса буде вигляду
`aktiv-test-a1b2c3.netlify.app`.

Приблизно **20 хвилин**, з них 4 — сама збірка.

Повна інструкція з доменом і вебхуком — у `netlify-deploy.md`. Цей файл
її не замінює, а йде перед нею.

## Крок 1. Перевірити, що збирається локально

Робити це на Netlify — марно палити час: там кожна помилка коштує
чотири хвилини збірки й читання логів.

```powershell
cd "C:\Users\Vlada Hnatok\Desktop\Шайко - сайт"

npm run check
npm run build
```

`npm run check` — типи, схеми Sanity, GROQ-запити й прогін калькулятора
на 432 комбінаціях. `npm run build` має закінчитись рядком
«Generating static pages (135/135)».

Якщо обидві команди зелені, на Netlify збірка впаде хіба що через
змінні середовища — а їх ми задамо на кроці 4.

## Крок 2. Репозиторій на GitHub

### 2.1. Перевірити, що секрети не поїдуть у git

**Це найважливіший крок усієї інструкції.** У `.env.local` лежить
`SANITY_API_WRITE_TOKEN` — токен **на запис**. Хто його отримає, зможе
переписати або стерти весь контент у Sanity.

```powershell
git init
git add .
git status --short | Select-String "\.env"
```

Порожній результат — добре. Якщо `.env.local` у списку, **не робіть
коміт**: перевірте, що `.gitignore` на місці й містить `.env*.local`,
потім `git rm --cached .env.local` і повторіть перевірку.

### 2.2. Коміт

```powershell
git add .
git commit -m "Сайт ЮК «АКТИВ»: тестовий деплой"
```

### 2.3. Репозиторій

На `github.com` → **New repository**:

- назва: `aktiv-site`
- **Private** — обов'язково. Публічність нічого не дає, а в коді є
  структура контенту клієнта
- **не** ставте галочки «Add a README», «Add .gitignore», «Choose a
  license» — інакше репозиторій буде непорожній і пуш дасть конфлікт

```powershell
git remote add origin https://github.com/ВАШ-АКАУНТ/aktiv-site.git
git branch -M main
git push -u origin main
```

Перший пуш попросить авторизуватись — GitHub відкриє вікно браузера.

## Крок 3. Створити сайт на Netlify

1. `app.netlify.com` → зареєструватись через GitHub
2. **Add new site** → **Import an existing project** → **GitHub**
3. **Configure the Netlify app on GitHub** → дати доступ до
   `aktiv-site` (можна тільки до нього, не до всіх репозиторіїв)
4. Вибрати репозиторій

Параметри збірки Netlify візьме з `netlify.toml` і питати не буде.
Якщо все ж показує порожні поля — значить файл не доїхав у git;
перевірте `git ls-files | Select-String netlify`.

**Поки не тисніть Deploy.**

## Крок 4. Змінні середовища

**Site configuration → Environment variables → Add a variable**,
scope — **All scopes**:

```
NEXT_PUBLIC_SANITY_PROJECT_ID    q2tr45a7
NEXT_PUBLIC_SANITY_DATASET       production
NEXT_PUBLIC_SANITY_API_VERSION   2026-01-01
```

Для тестового деплою цих трьох достатньо.

**`SANITY_REVALIDATE_SECRET` не потрібен** — вебхук ми не налаштовуємо,
а без секрету маршрут просто відповідає «не налаштовано» і нічого не
робить.

**`SANITY_API_WRITE_TOKEN` не додавайте ніколи.** Він потрібен лише
локально для `npm run seed`. На хостингу йому робити нічого, а лежати
там він буде як зайвий ризик.

## Крок 5. Збірка

**Deploy site.** 2–4 хвилини.

Якщо впало — **Deploys** → клік на невдалу збірку → лог. Дивіться на
перший червоний рядок, а не на останній: далі зазвичай іде каскад
наслідків.

### Часті причини

| У лозі | Причина | Що робити |
|---|---|---|
| `Unsupported engine … node` | Netlify взяв стару Node | перевірте, що `netlify.toml` доїхав у git: у ньому `NODE_VERSION = "22"` |
| `npm ci … lock file` | `package-lock.json` не в репозиторії | він **має** бути в git; перевірте, що `.gitignore` його не ловить |
| `Module not found` | файл не доїхав у git | `git ls-files <шлях>` — якщо порожньо, файл не додано |

## Крок 6. Що перевірити на живій адресі

Netlify дасть адресу вигляду `spontaneous-marzipan-a1b2c3.netlify.app`.
Її можна перейменувати: **Site configuration → Change site name**.

Пройдіться по списку — він складений так, щоб кожен пункт перевіряв
свій механізм:

1. **Головна** — заголовок «Рішення без виконання — не результат».
   *Перевіряє: збірка й статика.*
2. **`/sanity-check`** — сторінка діагностики. `projectId` зелений,
   «доступ: public». *Перевіряє: змінні середовища доїхали в рантайм.*
3. **«Нам довіряють»** на головній — якщо в стрічці їде «Моторола», а
   не службові заглушки «Клієнт 01», Sanity живий.
   *Перевіряє: запити до Sanity з сервера Netlify.*
4. **`/practices/likvidatsiya-bankrutstvo/alternative-liquidation`** —
   відкривається, не 404. *Перевіряє: 108 сторінок практик згенеровані.*
5. **`/team`** — 10 фахівців, у надзаголовку «Команда · 10 фахівців».
   *Перевіряє: підстановка {n} з живих даних.*
6. **`/about`** — місія, чотири цінності з іконками, п'ять принципів.
7. **Мови** — `/` віддає українську без префікса, `/en` і `/ru`
   працюють. *Перевіряє: proxy.ts на хостингу.*
8. **Телефон** — відкрийте головну з телефона. Бургер-меню,
   горизонтального скролу немає, кнопки зв'язку на місці.

### Якщо тексти не ті, що в студії

Це очікувано на тестовому деплої: **без вебхука** сторінки збираються
один раз, і правки в Sanity доїжджають лише до 5 хвилин (кеш) або до
наступної збірки. Щоб побачити зміну одразу — **Deploys → Trigger
deploy → Deploy site**.

Налаштовувати вебхук має сенс уже на справжньому домені (крок 6 у
`netlify-deploy.md`).

## Крок 7. Тестовий сайт закритий від пошуку сам

Адреса `*.netlify.app` доступна всім, хто її знає, і пошуковики могли
б її знайти. Для тесту юридичної фірми це небажано: старий сайт ще
працює, і два однакові сайти в індексі шкодять обом.

**Робити нічого не треба.** `robots.txt` сам дивиться, де зібраний
сайт:

- на `*.netlify.app` і в попередніх переглядах гілок — `Disallow: /`,
  індексація заборонена повністю;
- на `aktiv-alb.com` — відкрито, з посиланням на карту сайту.

Перевірити: відкрийте `https://ВАШ-САЙТ.netlify.app/robots.txt` — там
має бути два рядки, `User-Agent: *` і `Disallow: /`.

Раніше тут була порада дописати `noindex` вручну й не забути прибрати
перед запуском. Забути прибрати — означає запустити справжній сайт,
закритий від пошуку цілком, і дізнатися про це через місяць із
порожнього Search Console. Тепер це вирішується автоматично: привʼязали
домен — `robots.txt` відкрився.

Якщо потрібно закрити тест і від людей, а не лише від пошуковиків, —
**Site configuration → Build & deploy → Post processing → Password
protection** (на безкоштовному плані може бути недоступно).

## Крок 8. Далі

### Що вже працює саме собою

Кожен `git push` у `main` → Netlify збирає й публікує. Окремі гілки
отримують свої **deploy preview** адреси — зручно показувати правки,
не торкаючись основного тесту.

### Відкат

**Deploys** → попередня успішна збірка → **Publish deploy**. Миттєво,
без перезбірки.

### Коли переходити на справжній домен

Коли пройдено всі вісім пунктів кроку 6 і замовник подивився. Далі —
`netlify-deploy.md`, кроки 5–7: домен, HTTPS, вебхук.

Той самий сайт у Netlify можна залишити й просто додати йому домен —
створювати новий не треба.

### Прибрати тестовий сайт

**Site configuration → General → Delete this site**. Репозиторій на
GitHub при цьому залишається.
