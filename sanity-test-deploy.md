# Тестовий деплой разом із Sanity

Як викласти поточну версію на тестову адресу `*.netlify.app` так, щоб
контент у Sanity відповідав коду. Репозиторій і сайт на Netlify вже
створені (див. `github-setup.md` і `netlify-test-deploy.md`). Тут —
повторюваний цикл «оновив код → оновив Sanity → зібрав → перевірив».

Приблизно **15 хвилин**.

> **Головне правило:** ніколи не запускайте `npm run seed` без
> `--only`. Повний сид перезаписує практики й команду так, як вони
> описані в коді, і стирає все, що правили в студії: тексти, фото,
> відповідальних адвокатів.

---

## Що змінилось у Sanity цього разу

| Що | Де в студії | Як потрапляє в датасет |
|---|---|---|
| Ціни й калькулятори прибрані | — | `npm run cleanup:prices` (крок 3.1) |
| Сторінка «Карʼєра» | Контент → Сторінка «Карʼєра» | сид-заглушка (крок 3.2) |
| Вакансії | Контент → Вакансії | сид-заглушки з позначкою «приклад» (крок 3.2) |
| Адреса частинами, точка на карті | Налаштування сайту | вручну (крок 3.3) |
| Підпис практики під адвокатом | Команда → людина | вручну (крок 3.3) |

---

## Крок 1. Перевірити локально

```powershell
cd "C:\Users\user\Desktop\Шайко - сайт"

npm run check
npm run build
```

`check` перевіряє типи, схеми Sanity й GROQ-запити. `build` має
закінчитись без червоних рядків. Якщо тут падає — на Netlify впаде
так само, тільки повільніше.

---

## Крок 2. Студія

```powershell
npm run studio
```

Відкрийте <http://localhost:3333>. Студія береться з коду в цій папці,
тож нові розділи («Сторінка «Карʼєра»», «Вакансії») та поля адреси
зʼявляться самі. Окремо «деплоїти» студію не треба.

Жовта плашка **«Unknown field»** у практиках — це старі поля цін.
Їх прибирає наступний крок.

---

## Крок 3. Дані в Sanity

Усі команди — з вашого компʼютера, у другому вікні PowerShell (студію
не закривайте). Потрібен `SANITY_API_WRITE_TOKEN` у `.env.local`: він
там уже є.

### 3.1. Прибрати ціни

```powershell
npm run cleanup:prices
```

Це перегляд: скрипт покаже, що змінить, і нічого не запише. Якщо
список виглядає правильно:

```powershell
npm run cleanup:prices -- --apply
```

Стирає тільки ціни, калькулятори й поле `quiz`. Тексти, фото, варіанти
послуг і FAQ залишаються.

### 3.2. Заглушки для «Карʼєри»

Спершу сухий прогін:

```powershell
npm run seed -- --only=careerPage,vacancy --dry
```

Має показати 1 `careerPage` і 3 `vacancy`. Потім запис:

```powershell
npm run seed -- --only=careerPage,vacancy
```

Це безпечно запускати повторно: документи створюються **лише якщо їх
ще немає**. Вакансії, які фірма вже переписала під себе, сид не
торкається.

### 3.3. Адреса й підписи — вручну в студії

**Налаштування сайту:**

- «Адреса — вулиця й будинок»: `вул. Ділова, 6`
- «Адреса — офіс»: `офіс 25`
- «Місто»: `Київ`
- «Точка на карті»: як шукати офіс у Google Maps (можна лишити
  порожнім, тоді карта шукає за адресою)
- «Як знайти офіс»: підказка на картці, наприклад поверх або вхід

→ **Publish**.

**Команда** → кожна людина → «Практика — підпис під карткою» →
**Publish**. Якщо поле порожнє, сайт складе підпис із напрямів людини.

Чому не сидом: `--only=siteSettings` заново записує телефон, пошту,
цифри й тексти блоку довіри. Якщо їх правили в студії, правки
пропадуть. Вручну — пʼять полів і жодного ризику.

### 3.4. Перевірити датасет

```powershell
npm run sanity:doctor
```

Скрипт звертається до Sanity напряму, в обхід кешу, і показує, які
блоки сайту вже беруть дані з Sanity.

---

## Крок 4. Коміт і пуш

**GitHub Desktop** → вкладка **Changes**.

1. Прогорніть список. **Не має бути** `.env.local`, `node_modules/`,
   `.next/`, `.sanity/`. Якщо щось із цього є — не комітьте.
2. **Summary**: коротко, що змінилось, наприклад
   `Карʼєра, карта офісу, без цін`.
3. **Commit to main** → **Push origin**.

Netlify побачить пуш і почне збірку сам.

---

## Крок 5. Netlify

### 5.1. Змінні середовища

**Site configuration → Environment variables.** Має бути:

```
NEXT_PUBLIC_SANITY_PROJECT_ID    (id проєкту)
NEXT_PUBLIC_SANITY_DATASET       production
NEXT_PUBLIC_SANITY_API_VERSION   2026-01-01
```

- `SANITY_API_READ_TOKEN` потрібен **лише** тоді, коли `/sanity-check`
  на тестовому сайті показує приватний доступ. Токен — з правами
  Viewer.
- `SANITY_API_WRITE_TOKEN` на Netlify **не додавати ніколи**. Він
  потрібен тільки скриптам на вашому компʼютері.
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — за бажанням: тоді заявки
  з тестового сайту приходитимуть у Telegram.

### 5.2. Збірка

Якщо попередня збірка падала (наприклад, `ERR_INVALID_ARG_TYPE` на
`npm ci`), **Deploys → Trigger deploy → Clear cache and deploy site**.
Найчастіше причина в кеші Netlify, що лишився від іншої версії Node:
звичайна перезбірка бере його знову.

Далі вистачає звичайного пушу (крок 4).

---

## Крок 6. Що перевірити на тестовій адресі

1. **`/sanity-check`**: projectId зелений, доступ public.
2. **Головна**: цін і калькуляторів немає ніде, логотип у шапці завжди
   одного кольору.
3. **Блок контактів унизу**: картка офісу з адресою з кроку 3.3,
   темна карта. Поки cookie не прийняті, замість карти схема й кнопка
   «Показати карту».
4. **`/team` і блок «Команда» на головній**: під кожним адвокатом
   підпис практики.
5. **`/career`**: вакансії з позначкою **«приклад»**. На тестовій
   адресі їх видно навмисно, на `aktiv-alb.com` приклади сховаються
   самі.
6. **Телефон**: на будь-якій практиці натиснути «Консультація». Форма
   відкривається з підставленою послугою, нічого не розʼїжджається.
7. **`/robots.txt`**: `Disallow: /`. Тест закритий від пошуку
   автоматично.
8. **`/admin`**: демо-CRM. На Netlify заявки не зберігаються (напис
   «без збереження»), це очікувано до підключення бази.

## Правки в студії не видно на сайті

Без вебхука сторінки на тестовому сайті оновлюються раз на кілька
хвилин або після нової збірки. Щоб побачити одразу:
**Deploys → Trigger deploy → Deploy site** (кеш чистити не треба).

Вебхук налаштовується вже на справжньому домені: `netlify-deploy.md`.

---

## Часті проблеми

| Симптом | Причина | Що робити |
|---|---|---|
| `npm ci` падає з `ERR_INVALID_ARG_TYPE` | найімовірніше, кеш збірки від іншої версії Node | Clear cache and deploy (крок 5.2) |
| `Cannot find module @tailwindcss/postcss` | змінено команду збірки | повернути `netlify.toml` з репозиторію |
| Сайт показує тексти з коду, а не зі студії | змінні не доїхали | `/sanity-check`, крок 5.1, потім Trigger deploy |
| «Unknown field» у студії | старі поля цін | крок 3.1 |
| На `/career` порожньо | заглушки не засіяні | крок 3.2 |
| Стара адреса на картці | не заповнені поля адреси | крок 3.3 |

---

## Шпаргалка

```powershell
npm run check
npm run build
npm run cleanup:prices                        # перегляд
npm run cleanup:prices -- --apply             # запис
npm run seed -- --only=careerPage,vacancy     # тільки нове, безпечно
npm run sanity:doctor
```

Далі: студія (адреса, підписи) → GitHub Desktop (Commit, Push) →
Netlify (Clear cache and deploy, перший раз) → список із кроку 6.
